## v2에서 바뀐 것과 이유
v1은 정보를 다 보여 주려다 홈 2,066자·글자 스타일 22종·테두리 49개·회색 글씨 71%가 되어 "읽고 싶지 않은" 화면이 됐다.
v2는 **화면마다 하나의 메시지**: 첫 화면 = 사람(이름·직무·주력 기술) + 세 줄(문제→결과, 직접 구현, 숫자와 측정 기준) + 확대된 제품 화면 하나.
대표 작업은 결과를 반복하지 않고 **어떤 판단을 했는지**를 제목으로 쓴다. 설명·근거·대안은 케이스 페이지로.

## 0. 한 문장
**"무엇을 얼마나 했나"가 아니라 "어떤 문제를 끝까지 풀어 무엇이 달라졌나"를 5초 / 30초 / 3분 세 단계로 읽히게 한다.**

## 1. 읽는 시간별 설계 (정보 위계)

| 시간 | 읽는 사람의 질문 | 답하는 장치 |
|---|---|---|
| 5초 | 누구고, 믿을 만한가? | 이름 · 증거 문장 1줄 · 숫자 3개 · **성과 지도** |
| 30초 | 가장 잘한 일은? 본인이 한 게 맞나? | **대표 작업 3개** — 문제 → 결과 수치 → 영상 → 설계 결정 3개 |
| 3분 | 어떻게 생각하고 검증하나? | 케이스 페이지 — 현장, 제약, 구조, 결정과 효과, 검증 조건, 역할 분담, 발표자료, 회고 |
| 필요할 때 | 다른 건 뭐가 있나? | 전체 기록 — 연도별 표, 수상/오픈소스/활동 필터 |

펼쳐야 보이는 핵심은 없다. 접힌 것은 케이스 페이지 하나뿐이고, 들어가기 전 이미 결과 수치를 봤으므로 "왜 그렇게 됐는지" 궁금해서 연다.

## 2. 시그니처 시각화: 성과 지도
GitHub 잔디가 "꾸준함"을 한 장으로 말하듯, 성과 지도는 **"언제, 어떤 프로젝트에서, 어느 급의 결과가 났나"**를 한 장으로 말한다.

- 가로축: 실제 날짜(월 단위). 세로: 프로젝트 한 줄씩, **시작이 이른 것이 아래** → 오른쪽 위로 오르는 계단. 성장 궤적이 모양으로 보인다.
- 선: 프로젝트 기간. 표식: 수상·성과가 난 날짜.
- 표식 형태 = 등급 (색에만 의존하지 않음)
  - `●` 금색 채움: 상위 수상(대상·최우수·기관장상급)
  - `◆` 흰색: 수상(우수·장려)
  - `○` 빈 원: 본선·수료·참가
- 한 프로젝트에 상이 여러 개면 한 선 위에 표식이 여러 개 찍힌다 → "한 프로젝트를 여러 무대에서 검증받았다"가 저절로 보인다.
- 상위 수상은 상 이름을 선 옆에 직접 쓴다. 나머지는 마우스·초점 시 표시. 금색이 적을수록 금색이 의미를 가진다.
- 처음 열 때 선이 시간 순서대로 그려진다(0.9초, 1회). 동작 줄이기 설정이면 바로 완성된 상태.
- 줄을 누르면 해당 대표 작업/기록으로 이동.

임의 막대·점 장식이 아니라 **날짜라는 실제 값의 위치 인코딩**이다(RULES 5-50).

## 3. 대표 작업 스트립 (카드 반복 금지)
3개만. 카드 격자가 아니라 페이지 폭 전체를 쓰는 가로 띠. 각 띠의 구조:

1. 머리줄: 로고 · 이름 · 기간 · 팀 규모/내 역할 ……… 수상 칩(등급 표식 동일)
2. 왼쪽 5칸: **현장 한 줄**(명조, 사람의 장면) → 무엇을 만들었나 1문장 → **전/후 수치**(가장 큰 글자)
   오른쪽 7칸: 시연 영상/화면(화면에 들어오면 자동 재생, 음소거, 벗어나면 정지)
3. 설계 결정 3칸: `결정` → `왜` → `효과 수치`. "기술 설계가 기능에 준 영향"을 수치로 연결.
4. 각주: 측정 조건 · 케이스 스터디 · GitHub · 발표자료

## 4. 시각 언어
- **배경** 따뜻한 무채색 다크 `#101113`. 순흑·남색 슬레이트(전형적 AI 다크) 회피.
- **강조색 하나**: 금색 `#E3B341` = "상위 성과" 의미 전용. 링크·버튼에 쓰지 않는다. 보라/파랑 그라디언트 없음.
- **글꼴 두 개**: Pretendard(정보·숫자) + 마루 부리(사람의 장면 한 줄, 인용). 엔지니어링의 정확함과 사람의 온도를 글꼴로 분리.
- **크기 단계**: 16 · 18(본문) · 20 · 22(섹션 제목) · 24 · 36px. 16px 미만 없음(40~50대 노안 독자). 숫자 전부 `tabular-nums`.
- **글자색 3단계(APCA)**: `#ececec` Lc −95 · `#c9ccd1` Lc −75(필수 보조정보) · `#b4b7be` Lc −63(비필수 라벨). 모두 WCAG 7:1 이상.
- **선** 1px `#26282C`. 그림자·글래스·둥근 카드 남발 없음. 반경 2단계(6, 12).
- **모션** 성과 지도 1회 그리기 + 영상 재생 상태뿐. 스크롤 등장 애니메이션 없음.

## 5. 감성 설계 (심장을 울리는 부분)
화려함이 아니라 **사람**에서 나온다.
- 각 프로젝트는 숫자보다 먼저 **현장의 한 장면**으로 시작한다(명조): "반장은 매일 아침 허가서 40장을 손으로 맞춰 본다."
- 그 다음에 숫자가 온다. 장면 → 숫자의 순서가 "이 사람은 사람의 문제를 푼다"를 느끼게 한다.
- 케이스 끝의 **회고**("다시 한다면")는 겸손과 성장 속도를 보여 준다. 면접관이 가장 묻고 싶은 질문에 먼저 답한다.

## 6. 공학적 장치
- 데이터 하나(`content/site.json`) → 정적 HTML. 숫자(수상 수, 기간)는 데이터에서 계산, 손으로 쓰지 않음 → 과장 불가.
- JS 꺼져도 전부 읽힘. JS는 지도 상호작용·영상 재생 제어·필터만.
- **인쇄용 스타일**: Ctrl+P → 밝은 배경 2쪽 이력서로 변환. 인사팀이 출력·PDF 첨부할 때.
- 의존성 0, 빌드 `node scripts/build.mjs`, 배포 GitHub Actions → Pages.
