# 포트폴리오 웹사이트의 전달력: 이론·근거·검증 규칙

열람일: 2026-11-15. 대상: 한국 기업의 인사 담당자·개발 리드·연구 리드가 읽는 개인 포트폴리오 **양식**.
이 문서에서 전달력은 ‘문제·본인 행동·결과를 찾고, 정확히 이해하고, 근거로 확인하는 능력’으로 정의한다. 체류시간이나 클릭 수만으로 평가하지 않는다.
근거 표기: **연구**는 실험·관찰·연구 종합, **표준**은 접근성 요구사항, **실무**는 기관·기업의 가이드다. 각각 인과관계·적합성·실무 기대를 말하는 범위가 다르다.
**[추정]**은 연구를 이 사이트로 옮긴 설계 가설과 자체 합격선이다. 제안한 초·개수·픽셀·비율은 해당 연구가 입증한 최적값이 아니다.
검색 결과 요약만으로 인용하지 않았다. 아래 링크는 라이브 검색 후 실제 본문 또는 명시한 초록을 연 페이지다. 오류·차단으로 내용을 읽지 못한 페이지는 제외했으며, 직접 인용은 사용하지 않았다.

## 1. 시각 위계·게슈탈트·타이포 위계·그리드·여백

### 1.1 시각 위계: 중요도 차이를 지각 가능한 차이로 바꾼다

- **주장·기제:** 크기·굵기·명도 대비·배치가 주목 우선순위를 만든다. 모든 항목을 크게 강조하면 상대적 차이가 사라진다. 색 자체보다 주변과의 대비가 중요하다.
- **근거·한계:** NN/g의 시각 위계 가이드는 크기·대비·그룹화를 설명한다. 실무 원칙이며 특정 크기 비율이 채용 성과를 높인다는 실험은 아니다. [NN/g, 2021](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)
- **적용 [추정]:** 프로젝트 카드의 우선순위를 ‘해결한 문제/핵심 결과 → 증거 이미지 → 역할·기간 → 기술’로 고정한다. 가장 강한 강조는 카드당 1개만 두고, 5초 노출 뒤 처음 기억한 항목이 의도한 핵심인지 기록한다.

### 1.2 게슈탈트: 근접·유사·공통 영역·연속성·도형/배경

- **주장·기제:** 가까운 요소, 같은 형태, 같은 경계 안의 요소는 함께 해석되기 쉽다. 연결선·정렬은 연속성을, 배경과의 분리는 전경을 만든다. 서로 다른 그룹 단서가 충돌하면 소속이 모호해진다.
- **근거·한계:** Wagemans 등의 2012년 종설은 고전적·현대적 그룹화와 도형/배경 연구를 정리한다. 여기서는 PubMed 초록까지 확인했다. 화면 적용은 NN/g의 근접성 사례로 보완했다. 지각 원리가 특정 카드 모양을 의무화하지는 않는다. [연구 초록](https://pubmed.ncbi.nlm.nih.gov/22845751/), [근접성 가이드](https://www.nngroup.com/articles/gestalt-proximity/)
- **적용 [추정]:** 같은 프로젝트의 로고·결과·수상들을 한 영역에 둔다. 수상마다 프로젝트 카드를 복제하지 않는다. 그룹 간 간격을 그룹 내 간격의 2배 이상으로 시작하고, 모바일에서 ‘어떤 수상이 어느 프로젝트 소속인지’ 오답이 발생하면 조정한다.

### 1.3 타이포 위계: 크기보다 역할의 일관성

- **주장·기제:** 제목·설명·보조정보의 시각적 역할이 일정하면 다음 항목을 예측할 수 있다. 제목을 크게 하는 것과 구조를 이해시키는 것은 다르며, 의미 있는 제목과 문서 계층이 함께 필요하다.
- **근거·한계:** IBM Carbon은 본문·고정 제목·유동 제목 등을 토큰으로 구분한다. IBM의 제품·브랜드 체계이지 한글의 최적 폰트 크기를 검증한 연구는 아니다. [Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/type-sets)
- **적용 [추정]:** 크기 토큰은 본문·보조·소제목·대표 제목의 4단계로 시작하고 같은 역할에는 같은 토큰을 쓴다. 시각 계층과 HTML 제목 계층을 맞춘다. 한글은 `word-break: keep-all`, 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty`, 비교 숫자는 `tabular-nums`를 적용·검증한다.
- **검증 [추정]:** 360·768·1440 CSS px에서 제목 누락·겹침·본문 잘림 0건을 목표로 한다. 긴 URL·영문 식별자는 별도 줄바꿈을 허용한다. 위 CSS는 프로젝트 구현 선택이며 이론의 직접 결론은 아니다.

### 1.4 그리드·여백: 관계를 정렬하고 검색 위치를 고정한다

- **주장·기제:** 그리드는 반복 요소의 위치를 예측하게 하는 설계 체계다. 여백은 가까운 내용을 묶고 다른 내용을 분리하는 정보다. 여백이 많을수록 무조건 좋다는 법칙은 없다.
- **근거·한계:** Carbon 2x Grid는 8px 기본 단위와 열·여백 체계를 사용한다. 이는 일관성을 위한 공식 설계 관례이며 8px 자체의 인지적 우월성 증명은 아니다. 근접성 연구의 UI 적용이 여백의 관계 표현을 뒷받침한다. [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)
- **적용 [추정]:** 섹션 제목·프로젝트 본문·그림의 좌우 기준선을 통일하고 주요 간격은 8·16·24·32·48px 토큰으로 시작한다. 카드 제목과 본문 사이보다 이전 카드와 다음 제목 사이를 더 넓게 둔다. 여백 때문에 결과가 첫 화면에서 밀리면 해당 간격부터 줄인다.

## 2. 시선 이동: F·Z·레이어케이크와 한국어 화면

### 2.1 F 패턴은 고정 배치도가 아니라 특정 읽기 행동이다

- **주장·근거:** NN/g 관찰에서 F 패턴은 상단을 가로로 읽고 아래로 내려가며 줄 앞부분 위주로 훑는 경향이다. 특히 제목·강조가 부족한 긴 본문에서 나타나며, 중요한 내용을 놓칠 수 있다. 원문도 모든 독자가 F로 읽는다고 해석하지 말라고 설명한다. [NN/g, 2017/2026 검토](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)
- **적용 [추정]:** 결과와 문제를 첫 두 문장에 놓고, 제목·불릿의 앞부분에 구별되는 핵심어를 둔다. 모든 불릿을 ‘프로젝트에서’처럼 같은 말로 시작하지 않는다. 첫 문장만 모아 읽어도 각 프로젝트의 차이가 식별되는지 검수한다.
- **한계:** 집단 시선 히트맵은 개인의 정확한 읽기 순서가 아니다. 시선 고정은 이해·동의·긍정 평가를 뜻하지 않으므로 내용 회상 질문을 별도로 둔다.

### 2.2 국내 연구와 Z 패턴: 과제·언어·레이아웃을 함께 봐야 한다

- **국내 근거:** 황미경 외(2022)는 네이버·다음·줌·네이트를 다루며 메인 페이지의 Z형 레이아웃, 뉴스·검색 페이지의 F형, 사진·헤드카피 및 상단의 시선 집중을 보고했다. **KCI 초록만 확인**했으므로 표본·자극 통제·효과 크기는 검증하지 못했다. [논문 초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002812814)
- **보완 연구:** Dong·Lee(2008)는 각 집단 9명씩, 총 27명의 유효 시선 데이터를 분석했다. 같은 구성의 모국어 포털 시제품을 클릭 없이 자유 관찰하게 했으며, 한국·중국 참가자에게 영역 간 왕복·원형 탐색이 더 나타났다. 소표본·옛 포털·자유 관찰 조건이므로 ‘한국인은 항상 원형으로 읽는다’는 결론은 부적절하다. [연구 전문](https://ijdesign.org/index.php/IJDesign/article/view/267/163)
- **적용 [추정]:** Z는 간결한 화면에서 우선순위를 점검하는 스케치로만 쓴다. 대각선 끝에 필수 정보를 배치하는 규칙으로 만들지 않는다. 한국어 프로젝트 3개 이상에서 ‘역할 찾기·결과 찾기·증거 찾기’를 각각 수행시켜 완료 시간과 오답을 측정한다.
- **근거의 공백:** 확보한 국내 연구는 한국어 포털 화면의 시선 자료다. 한글 자체의 효과와 레이아웃·문화·과제의 효과를 분리하거나 한국 채용 포트폴리오의 최적 패턴을 증명하지는 않는다.

### 2.3 레이어케이크: 제목만 훑어도 내용을 고를 수 있게 한다

- **주장·근거:** 눈이 제목·소제목을 따라 이동하다 필요한 본문만 읽는 패턴이다. 일관된 제목 모양, 본문 소속이 명확한 간격, 내용을 예측하게 하는 제목이 전제다. [NN/g 관찰·가이드, 2019](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)
- **적용 [추정]:** ‘Overview·Process·Result’만 반복하지 말고 ‘응답 지연의 원인’, ‘검색 범위를 제한한 이유’처럼 판단할 내용을 제목에 쓴다. 제목만 보여준 상태에서 원하는 근거가 있는 절을 10초 안에 고르는지 확인한다.

## 3. 정보 냄새·점진적 공개·인지 부하·청킹

### 3.1 정보 냄새: 열기 전에 얻을 답과 비용을 예측한다

- **주장·기제:** 독자는 링크 이름·주변 맥락·이전 경험으로 목적지의 가치와 탐색 비용을 추정한다. 정보가 많아도 무엇을 얻는지 모르면 다음 클릭을 선택하기 어렵다.
- **근거·한계:** NN/g는 정보 탐색 이론에 기반해 링크의 예상 효용을 설명한다. 원래 이론의 논문은 열람에 실패해 출처로 사용하지 않았으며, 여기서는 NN/g의 실무 해설 범위에 한정한다. [Information Scent, 2020](https://www.nngroup.com/articles/information-scent/)
- **적용 [추정]:** ‘더 보기’를 ‘검색 실패 사례와 수정 근거’, ‘PDF’를 ‘실험 설계 발표자료 · 웹 열람’처럼 바꾼다. 접기 제목에 실제 포함 내용·형식을 표시한다. 열기 전 예상한 내용과 열린 내용이 일치하는지를 사용자에게 확인한다.

### 3.2 점진적 공개: 핵심 판단 뒤에 세부 복잡성을 배치한다

- **주장·근거:** 자주 쓰거나 중요한 정보는 먼저, 부차적·전문적 기능은 요청할 때 제공한다. 원래는 응용프로그램 기능 설계 원칙이므로 포트폴리오 정보 구조로의 전이는 [추정]이다. [NN/g, Progressive Disclosure, 2006](https://www.nngroup.com/articles/progressive-disclosure/)
- **적용 [추정]:** 문제·본인 역할·핵심 결과·대표 증거는 기본 상태에서 공개한다. 상세 로그·실험 전체 표·보조 수상은 접을 수 있다. 결과 확인에 필요한 펼치기 0회, 상세 근거 도달은 1회 이내를 목표로 한다.
- **검증 [추정]:** 키보드로 펼치기·접기 가능, 포커스 유지, 열림 상태 전달을 확인한다. 접힌 내용이 없어도 30초 설명이 완성되는지, 열었을 때 새 근거가 추가되는지 따로 검사한다.

### 3.3 인지 부하: 독자가 수행해야 하는 변환을 줄인다

- **주장·근거:** Sweller(1988)는 문제 풀이에 드는 처리 요구가 도식 학습을 방해할 수 있음을 모델과 실험으로 제시했다. 학습·문제 풀이 연구이므로 포트폴리오의 합격률을 직접 설명하지 않는다. [논문 전문](https://www.waddesdonschool.com/wp-content/uploads/2021/02/Cognitive-Load-Theory-Sweller-J-1988.pdf)
- **적용 [추정]:** 기술명과 사용자 영향을 같은 위치에 연결한다. 예컨대 ‘RAG → 근거 문서 검색 → 답변 출처 확인’처럼 설명하고 실제 증거를 붙인다. 멀티턴·XAI·뉴로심볼릭도 각각 기능·판단 변화와 연결하며 용어 목록만 두지 않는다.
- **검증 [추정]:** 설명과 그림을 서로 다른 화면에서 기억해 대조하게 하지 않는다. 비전문가가 기술이 바꾼 동작을 자기 말로 설명하는지 확인한다. ‘어려워 보임’과 ‘불필요한 해석 작업’을 구분하고 필요한 기술적 깊이는 보존한다.

### 3.4 청킹: 같은 질문에 답하는 요소를 의미 단위로 묶는다

- **주장·근거:** Cowan(2001)은 리허설·장기기억 재부호화 등이 제한된 조건에서 약 3~5개 청크의 저장 용량을 논의했다. 이는 메뉴·카드 수를 4개나 7개로 제한하는 규칙이 아니다. 화면을 다시 볼 수 있는 인식 과제와 기억 과제도 다르다. [논문 전문](https://memory.psych.missouri.edu/assets/doc/articles/2001/cowan-bbs-2001.pdf)
- **적용 [추정]:** 카드 요약을 ‘문제·행동·결과’의 3묶음으로 시작하되, 근거가 잘리면 묶음 수를 늘린다. 여러 프로젝트에서 역할·기간·결과의 위치를 통일한다. 독자가 요소의 의미를 모른다면 테두리로 묶었다는 이유만으로 청킹에 성공했다고 보지 않는다.

## 4. 설득·스토리텔링: 결론과 검증 경로

### 4.1 역피라미드: 중간에 읽기를 멈춰도 요지는 남긴다

- **주장·근거:** 결론·핵심 사실을 앞에 두고 설명과 배경을 뒤로 보낸다. NN/g는 웹의 훑어읽기와 다양한 읽기 깊이에 맞는 편집 방식으로 권한다. 설득 효과의 보편적 인과 증명은 아니다. [Inverted Pyramid, 2018](https://www.nngroup.com/articles/inverted-pyramid/)
- **적용 [추정]:** 프로젝트의 첫 문장을 ‘어떤 문제에 무엇을 바꿨고 어떤 결과를 확인했는지’로 쓴다. 배경은 그다음에 둔다. 첫 문장·첫 카드·상세 본문 중 어느 지점에서 멈춰도 서로 모순되지 않는 결론을 얻게 한다.

### 4.2 STAR·PAR·문제–해결–결과: 행동의 근거와 주체를 드러낸다

- **주장·근거:** STAR는 상황·과제·행동·결과, PAR는 문제·행동·결과를 점검하는 서술 틀이다. 영국 National Careers Service와 Virginia Tech는 구체 경험의 설명에 권한다. 구조화 조언이지 특정 순서가 취업을 보장한다는 연구는 아니다. [STAR 공식 가이드](https://nationalcareers.service.gov.uk/careers-advice/interview-advice/the-star-method/), [PAR 대학 가이드](https://tips.career.vt.edu/Resumes/bulletformula.html)
- **적용 [추정]:** 요약에서는 결과를 먼저, 상세에서는 ‘문제와 제약 → 대안 → 선택과 본인 행동 → 관찰 결과 → 한계’를 연결한다. 팀이 한 일과 본인이 한 일을 문장 주어로 분리하고, 핵심 결정마다 선택 이유 1개와 증거 1개를 둔다.
- **한계·검증:** 전후 차이만으로 내 행동이 원인이라고 단정하지 않는다. 비교군이 없다면 ‘변경 후 관찰’로 쓰고 데이터·환경의 동시 변화도 기록한다. STAR에 맞추려고 성공담·수치·갈등을 만들지 않는다.

### 4.3 한국 자기소개서의 두괄식: 평가 질문에 먼저 답한다

- **국내 근거:** 명지대 현장실습 안내는 직무 관련 핵심을 두괄식·소제목으로 표현하고, 프로젝트의 이유·본인 역할·문제 해결·성과를 담도록 안내한다. 특정 기관의 작성 지침이며 한국 채용자 전체의 읽기 법칙은 아니다. [명지대 안내 PDF, p.4](https://teaching.mju.ac.kr/bbs/mjukr/146/172527/download.do)
- **적용 [추정]:** 첫 문장을 성격 표어로 채우지 말고 해당 프로젝트에서 입증할 역량과 사실로 쓴다. 문장마다 ‘누가·무엇을·왜·어떤 결과로’ 중 필요한 요소가 있는지 확인한다. 글자 수 권고는 자소서 문항용이므로 웹 카드에 그대로 적용하지 않는다.

## 5. 데이터 시각화: 성과의 크기와 의미를 함께 전달한다

### 5.1 Tufte의 데이터잉크: 장식을 줄여 비교 가능한 정보를 남긴다

- **주장·근거:** 데이터잉크 비율은 전체 잉크 중 데이터 표현에 쓰인 잉크의 비중이다. Tufte는 스파크라인의 비데이터 요소를 줄이되 주변 숫자·단어에서 정량적 맥락을 얻는다고 설명한다. 미학적·분석적 설계 원칙이며 비율 극대화가 모든 과제의 정답이라는 실험 결과는 아니다. [Tufte, Sparklines History](https://www.edwardtufte.com/notebook/)
- **적용 [추정]:** 차트의 테두리·배경 무늬·입체 효과를 지웠을 때 해석이 유지되면 삭제한다. 단위·축·기준선·출처·불확실성은 해석에 필요하면 남긴다. 모든 시각 요소에 ‘값·비교·구조·설명 중 무엇을 전달하는가’를 답할 수 있게 한다.
- **주의:** ‘잉크를 줄인다’를 ‘맥락을 지운다’로 해석하지 않는다. 활동 날짜만 나열한 타임라인은 시간 구조를 보여줄 수 있지만, 문제 해결 효과를 비교하는 성과 시각화는 별도로 필요하다.

### 5.2 사전주의 속성: 빠른 발견과 정확한 해석을 구분한다

- **주장·근거:** 색·방향·크기 등의 차이는 일부 탐색 과제에서 빠르게 발견된다. Healey는 약 200~250ms 이내 과제와 속성 간 간섭·결합 탐색의 한계를 설명하며, 초기 지각에도 주의의 역할이 있음을 강조한다. [연구자 해설·연구 연결](https://www.csc2.ncsu.edu/faculty/healey/PP/index.html)
- **적용 [추정]:** 비교 차트에서 핵심 변화 1개만 강조색으로 표시하고 나머지는 중립색으로 둔다. 좋아짐·나빠짐은 색 외에 부호·직접 라벨로도 표시한다. 독자가 가장 큰 변화와 그 방향을 각각 맞히는지 확인한다.

### 5.3 그래픽 지각: 크기 비교에는 공통 척도를 우선한다

- **주장·근거:** Heer·Bostock(2010)은 비율 추정 과제로 기존 그래픽 지각 실험을 재현·확장했다. 공통 척도상의 위치는 길이·각도·면적보다 정확한 비교에 유리한 결과를 보였다. 다만 길이와 각도의 모든 우열이 지지된 것은 아니다. [CHI 논문 전문](https://idl.cs.washington.edu/files/2010-MTurk-CHI.pdf)
- **적용 [추정]:** 전후 비교는 같은 축의 점·막대, 여러 조건은 같은 척도의 작은 반복 차트로 표현한다. 막대는 길이를 왜곡하지 않도록 0에서 시작한다. 축 절단이 필요한 점·선 차트는 범위를 드러낸다. 정확한 값은 직접 표기하고 표·텍스트로도 제공한다.

### 5.4 비교 기준 없는 숫자: 크기는 있어도 평가 근거가 없다

- **주장·근거:** 비교 대상·정규화 기준에 따라 수치 해석이 달라진다. 열린 교재는 비교 가능한 데이터와 분모의 중요성을 설명한다. Tufte도 작은 차트 주변의 수치 맥락을 강조한다. [Hands-On Data Visualization, 비교 장](https://handsondataviz.org/comparisons.html)
- **적용 [추정]:** 성과 수치마다 ‘지표 정의·단위·기준값·변경값·기간/표본·측정 조건·출처’를 확인한다. 평균·중앙값·p95를 섞지 않고, 비율 변화와 퍼센트포인트 변화를 구분한다. 비교 불가 항목은 동일 순위 차트에 넣지 않는다.
- **양식 규칙:** 실제 값이 없으면 빈 필드·미측정 상태로 둔다. 양식 검수용 가짜 값은 해당 항목에서 예시임을 명시한다. 가짜 정확도·사용자 수·향상률을 실적처럼 쓰지 않는다. 수상은 주최·대회·부문·날짜·공식 근거로 표시하고 서비스 성능 지표와 구분한다.

## 6. 케이스 스터디 작성법: 결과물과 판단 과정의 연결

### 6.1 디자이너 포트폴리오: 최종 화면만으로는 의사결정을 알 수 없다

- **근거:** NN/g는 UX 채용 담당 업무를 하는 204명의 설문을 바탕으로 문제·역할·제약·반복 과정·조사에 따른 설계 변화를 강조한다. 채용자의 보고된 선호이며 실제 합격률 실험은 아니다. [UX-Design Portfolio 가이드, 2019](https://www.nngroup.com/articles/ux-design-portfolios/)
- **적용 [추정]:** 사례마다 문제·역할·제약·선택·결과·한계를 포함한다. 리서치 산출물을 전부 나열하기보다 결정을 바꾼 자료를 선택한다. 최소 1개의 ‘관찰 → 판단 → 화면/기능 변화 → 검증’ 연결이 그림과 짧은 설명으로 읽혀야 한다.

### 6.2 국내 UX·디자인 가이드: 문제 해결과 직무 적합성

- **근거:** 토스는 2022년 글에서 문제 해결 질문 5개와 이미지 1장으로 초기 평가를 구성한 사례를 설명한다. 삼성 디자인의 2024년 안내는 직무에 맞는 프로젝트 선정과 팀 인원·본인 역할·기여도 명시를 권한다. 과거 해당 전형의 설명이며 현재 모든 기업의 공통 제출 규정이 아니다. [토스](https://toss.tech/article/2022-product-designer-challenge), [삼성 디자인 Q9~12](https://design.samsung.com/kr/contents/design-career-3/)
- **적용 [추정]:** 대표 프로젝트의 선택 이유를 지원 직무와 연결해 설명할 수 있어야 한다. 인원·역할·기간을 고정 위치에 표시하고 근거 없는 기여도 퍼센트는 쓰지 않는다. 웹 요약이 완결된 다음 발표자료를 웹에서 펼쳐 보게 한다.
- **검증 [추정]:** 국내 인사·개발·연구 관점에서 각각 ‘문제와 결과’, ‘설계 이유와 동작’, ‘평가 조건과 한계’를 찾게 한다. 한 사람이 모든 관점을 대변했다고 간주하지 않는다.

### 6.3 개발자 포트폴리오: 실행·코드·설명으로 주장에 접근하게 한다

- **근거:** GitHub 공식 가이드는 대표 프로젝트 3~5개, 간결한 README, 주요 기능·설치/실행·데모·테스트 안내를 권한다. GitHub 프로필을 위한 실무 조언이며 독립 웹사이트의 필수 개수는 아니다. [GitHub 공식 가이드](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)
- **적용 [추정]:** 사이트에서는 시연을 바로 보고 핵심 기능을 이해하게 하며, 코드·실행·검증 안내로 이어지는 링크를 둔다. 설계 그림의 구성요소를 사용자 동작과 연결하고, 주장한 기능에 대응하는 실행 결과나 테스트 근거를 최소 1개 연결한다.
- **구성 [추정]:** 프로젝트를 기본 단위로 묶고 카드 내부의 개발·발표·수상 사건은 날짜순으로 정리한다. 사건 개수를 역량 점수로 바꾸지 않는다. 대표 사례 선정과 전체 시간 흐름은 서로 다른 질문이므로 함께 식별 가능하게 한다.

## 7. 첫인상·신뢰 형성

### 7.1 50ms 첫인상: 빠른 미적 판단의 증거

- **연구:** Lindgaard 외(2006)의 세 번째 실험은 40명을 50ms·500ms 조건에 20명씩 배정해 홈페이지 시각적 매력을 평정하게 했다. 두 노출 조건의 평정이 높은 상관을 보였다. 내용 이해·신뢰의 진위·채용 판단을 50ms에 측정한 실험은 아니다. [논문 전문, Study 3](https://www.makinggood.ac.nz/media/1265/lindegaardetal_2006_attention.pdf)
- **적용 [추정]:** 초기 화면에서 정렬·서체·이미지 해상도·강조 우선순위를 일관되게 만든다. 핵심 문장이 긴 등장 애니메이션 뒤에 나타나지 않게 한다. 5초 노출 후 문제·행동·결과 회상을 측정하되 이를 50ms 연구의 재현이라고 부르지 않는다.

### 7.2 웹 신뢰성: 보기 좋은 주장에 확인 가능한 근거를 붙인다

- **근거:** Stanford Web Credibility 프로젝트는 3년간 4,500명 이상을 포함한 연구를 토대로 검증 가능한 정보, 전문성, 목적에 맞는 디자인, 사용성, 최신성, 오류 최소화를 권고한다. 2002년 지침으로 현대 포트폴리오의 효과 크기를 직접 추정할 수는 없다. [Stanford Guidelines](https://credibility.stanford.edu/guidelines/index.html)
- **적용 [추정]:** 성과 옆에 공식 수상 기록·배포물·저장소·평가 자료 중 해당 증거를 연결한다. 각 프로젝트의 작성/검토 시점과 팀·개인의 성과 구분을 명시한다. 끊어진 링크·가짜 배지·작동하지 않는 데모 0건을 목표로 한다.
- **검증 [추정]:** 인상을 묻는 질문과 ‘이 주장을 확인할 수 있는가’를 분리한다. 원 지침의 연락처 권고를 이 저장소에서 금지한 연락하기 CTA로 바꿔 적용하지 않는다. 신뢰를 높인다는 이유로 불필요한 개인정보를 추가하지 않는다.

## 8. 다크 테마에서 읽기

### 8.1 선호·편안함과 읽기 수행은 별개다

- **연구:** Piepenbrock·Mayr·Buchner(2014)는 밝은 배경/어두운 글자의 양극성 표시에서 동공이 더 작고 교정 읽기 성능이 더 좋은 결과를 보고했다. 밝기에 관한 설명과 양립하지만 모든 조건에서 다크가 열등하다거나 장기적 눈 건강을 판정한 연구는 아니다. [논문 전문](https://www.psychologie.hhu.de/fileadmin/redaktion/Oeffentliche_Medien/Fakultaeten/Mathematisch-Naturwissenschaftliche_Fakultaet/Psychologie/AAP/Publikationen/in_press/Piepenbrock-in_press-Smaller_pupil_size_and_better.pdf)
- **적용 [추정]:** 사용자의 다크 선호를 유지하되 작은 회색 본문·얇은 글자·긴 연속 문단을 피한다. 본문 16~18px·행간 1.6~1.8을 시작점으로, 밝은 실내와 어두운 환경에서 같은 내용의 읽기 오류·완료 시간·편안함을 각각 측정한다.
- **한계:** 순검정 금지나 특정 회색 배경을 보편적 생리 법칙으로 제시하지 않는다. 이 연구만으로 한글 글꼴·현대 디스플레이·개별 사용자의 최적 배경색을 정할 수 없다.

### 8.2 대비: 밝기를 낮춰도 읽을 수 있는 차이는 남긴다

- **표준:** WCAG 2.2 SC 1.4.3(AA)은 일반 텍스트 4.5:1, 큰 텍스트 3:1 이상을 요구한다. 큰 텍스트는 통상 18pt 또는 굵은 14pt 이상이며 동아시아 글꼴은 동등 크기를 고려한다. SC 1.4.11(AA)은 식별에 필요한 UI·그래픽 정보에 인접 색 대비 3:1을 요구한다. [규범 표준](https://www.w3.org/TR/WCAG22/), [텍스트 대비 해설](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- **적용:** 본문뿐 아니라 날짜·캡션·축 라벨·링크·펼치기 상태도 해당 기준으로 검사한다. 모든 장식용 테두리에 3:1을 요구하는 것은 아니다. 대비 통과만으로 편안한 읽기가 보장되지는 않는다.
- **적용 [추정]:** 작은 텍스트는 크기 예외에 기대지 않고 4.5:1을 확보한다. 기본·호버·포커스 상태를 모두 점검하며, 밝은 포스터/발표 슬라이드가 화면 대부분을 차지할 때의 눈부심도 사용자 평가에 포함한다.

### 8.3 행 길이·간격·확대: 사용자가 읽기 조건을 조절해도 유지한다

- **표준:** SC 1.4.12(AA)은 행간 1.5배·문단 뒤 2배·자간 0.12em·단어 간격 0.16em으로 사용자가 바꿔도 손실이 없어야 한다. 이는 기본 스타일을 그 값으로 설정하라는 뜻이 아니다. [Text Spacing 해설](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- **표준:** SC 1.4.8(AAA)은 CJK 40자 이내 행 폭, 양쪽 맞춤 회피 등으로 조정할 수 있는 수단을 다룬다. AA 필수 기준으로 혼동하지 않는다. [Visual Presentation 해설](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)
- **적용 [추정]:** 한글 본문은 데스크톱에서 대략 25~40자 행 길이를 시작점으로 삼고 실제 렌더링으로 확인한다. 200% 글자 확대·간격 재설정·320 CSS px 폭에서 읽기와 조작을 검수한다. 긴 식별자·도표에는 필요한 대체 표현을 제공한다.

## 포트폴리오 웹사이트 설계에 바로 쓰는 시사점

아래 수치 합격선은 별도 표시한 접근성 기준 외에는 모두 **[추정]**이다. 프로젝트 3개 이상이 있는 양식으로 검수하고, 예시 값을 실제 실적으로 평가하지 않는다. 각 관점 1명은 탐색적 검수의 시작일 뿐 통계적 검증 표본이 아니며, 아래 테스트는 아직 수행하지 않았다.

1. [ ] 첫 화면을 5초 본 뒤 국내 인사·개발·연구 관점의 검토자 각 1명 이상이 대표 문제와 결과를 정확히 말한다.
2. [ ] 모든 프로젝트에서 문제·본인 역할·핵심 결과·대표 증거가 펼치기 없이 보이고, 가장 강한 시각 강조가 1개다.
3. [ ] 같은 프로젝트의 여러 수상이 한 영역에 묶이며, 프로젝트별 사건의 날짜순과 각 수상의 소속을 혼동 없이 읽을 수 있다.
4. [ ] 제목만 읽어도 사례의 차이가 드러나고, 원하는 근거가 있는 절을 10초 안에 찾을 수 있다.
5. [ ] 모든 펼치기·자료 링크가 목적 내용을 예고하며, 상세 근거에 1회 이내 조작으로 도달하고 키보드로도 사용할 수 있다.
6. [ ] 각 사례에 ‘문제·제약 → 본인 선택 → 기능 변화 → 결과·한계’가 연결되어 있고 이를 설명하는 그림이나 시연이 최소 1개 있다.
7. [ ] 모든 성과 숫자에 단위·비교 기준·측정 조건·출처가 있으며, 없는 값은 미측정/예시로 구별되고 가짜 실적으로 읽히지 않는다.
8. [ ] 대표 시연을 페이지에서 바로 볼 수 있고 발표자료도 웹에서 열람되며, PDF를 열지 않아도 핵심 설명이 완결된다.
9. [ ] 본문·보조 텍스트·필수 UI/그래픽이 해당 WCAG 대비 기준을 통과하고, 200% 글자 확대·간격 재설정·좁은 화면에서 정보가 사라지지 않는다.
10. [ ] 세 검토자군의 탐색 시간·정답 여부·주장 확인 가능성을 각각 기록하고, 끊어진 증거 링크·불명확한 본인 기여·장식만 있는 성과 차트가 0건이다.
