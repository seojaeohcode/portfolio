# 조사 종합 → v3 설계 규칙

근거: A 인사(24개 출처) · B 기술팀(23) · C 합격자 사례(12+4) · D 이론 · E 한국 서비스 UI. 핵심 출처 3개(토스 FE 리포지토리 전형, 우아한형제들 신입 합격 회고, 사람인 263개사 조사)는 원문 대조 완료.

## 조사가 말하는 것 (여러 갈래에서 반복된 것만)
1. **먼저 보는 건 직무 적합도.** 신입 서류는 평균 6~13분, 40%는 중요한 부분만 골라 읽음(A-S01·S05). "몇 초 만에 탈락" 통계는 근거 없음 → 빨리 훑기와 깊게 읽기를 둘 다 지원.
2. **팀 결과와 내가 한 일을 분리.** 직접 설계·구현·검증한 범위, 결정과 대안, 코드·PR로 연결(A3, B 공통, 토스·당근 공고).
3. **숫자는 단위·전후·조건과 함께.** 근거 없는 숫자는 "검증 대상"이 됨. 미측정은 미측정으로(B 표, D 5.4).
4. **수상은 프로젝트에 붙여 맥락과 함께.** 일반 설문에선 영향이 낮지만 AI 직무엔 관련 수상 우대(A-S03·S18).
5. **링크를 안 열어도 핵심이 이해돼야** 하고, 링크 이름은 열면 무엇이 나오는지 알려야 함(A8, B, D 3.1 정보 냄새).
6. **같은 틀, 같은 위치.** 프로젝트마다 이름·기간·역할·결과를 같은 자리에서 찾게(C, E-12, 네이버 공고 목록).
7. **대표 하나를 깊게.** 첫 화면에서 한 프로젝트를 완전히 이해시키기(E-1, 우아한 회고 "자신 있는 프로젝트 하나").
8. **기술 → 기능 변화를 한 행에.** 기술 배지 나열 금지, 숙련도 막대 금지(C, E-7, D 3.3).
9. **PDF 제출이 흔함**(토스·당근). 웹과 내용이 같은 PDF가 필요(A-10).
10. **카드는 프로젝트에만**, 이력은 행으로(E-4). 같은 프로젝트의 요소는 한 영역에(게슈탈트 공통 영역).

## 이전 버전이 실패한 이유
- v1: 정보를 전부 펼침 → 글자 벽. v2: 첫 화면 요약 → 아래에서 같은 내용 반복, 역할이 늦게 나옴, 세 프로젝트가 서로 다른 위치·형식.
- 둘 다 "프로젝트 하나를 끝까지 이해시키는 단위"가 없었다.

## v3 구조
1. 머리줄: 이름 · 링크(GitHub, 이메일, PDF 이력서). 버튼 아님.
2. 신원: 이름(32) → 직무·졸업·학교(17) → 주력 기술 → 대표 작업 목차(이름 + 한 줄 설명 앵커).
3. **프로젝트 카드 ×3 (같은 틀)**: 첫 카드가 첫 화면 안에 들어온다.
   - 왼쪽: 순번·기간·팀·상태 → 제목(문제→결과) → 현장 한 줄 → 대표 지표(이름, 전→후 막대 같은 축, 측정 조건) → 직접 구현 → 수상(날짜·대회·결과·주최)
   - 오른쪽: 시연(영상/화면) + 무엇을 보여 주는지 한 줄
   - 아래: "기술 선택이 바꾼 것" 행(효과 숫자 | 결정 | 이유), 개수는 프로젝트마다 다름
   - 링크: 내용이 예고되는 이름("설계·대안·실험 조건·실패 사례", "발표자료 3쪽 웹 보기")
4. 전체 기록: 성과 지도 + 연도별 목록.
5. 케이스 페이지 제목은 판단이 보이게("88%는 이렇게 쟀습니다", "안 된 것과 고친 것"), 실패는 증상→원인→조치→검증.
6. `/resume/` 인쇄용 1~2쪽 + CI에서 PDF 생성.

## 검수 기준
- 첫 화면(1440×900, 390×844)에서: 이름·직무·주력, 프로젝트 1의 문제·직접 구현·지표(조건 포함)·시연이 모두 보임.
- 세 카드의 같은 항목이 같은 위치. 숫자 옆 조건 100%. 링크 이름에 목적지 내용.
- 블라인드 테스트: 조사에서 나온 실제 발언 근거로 만든 페르소나(인사·개발 리드·AI 연구 리드·토스급 디자이너).

## v4 (읽기 흐름 개선)
- 측정: v3 카드 하나에 글 조각 50개·글자 스타일 11종·회색 라벨 31개 → 읽는 글이 아니라 서식.
- 카드를 3층으로: ① 제목(문제→결과) + 현장 한 줄 ② 큰 숫자 하나 + "무엇을 몇 개로 쟀나" + 실제 업무 효과 한 줄 ③ 개조식 세 줄(직접 만든 것 / 핵심 판단 → 결과 / 수상).
- 설계 결정 전체·팀 역할·측정 세부는 상세 페이지로. 카드 조각 50 → 약 20, 글자 수 약 500 → 300, 카드 높이(데스크톱) 약 1,600px → 650px.
- 블라인드 A/B 읽기 테스트: v3 5/10 → v4 8/10.
