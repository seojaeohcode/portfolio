- 조사일: 2026-11-16. 대상: 개발과 응용연구를 함께 수행한 신입.
- 공식 공고·안내, 영상 자막·블로그 정리를 직접 열람. 과거 전형은 연도 표시. 공개 JD는 업무·자격의 근거이며, 비공개 서류 배점표가 아님.

- **FDE 비교 기준:** 열람한 위 11개사 자료에서 동일 명칭의 신입 FDE 기준은 확인하지 못함. 별도 기업 Superb AI의 신입 가능 공고는 “실제로 무언가를 끝까지 만들어본 경험”, 현장 배포·실데이터 개선·재사용 문서를 요구. [S13][S13]
- **경력 기준과 구분:** Superb AI 시니어 FDE는 데이터·평가지표 설계부터 배포·운영까지 전체 책임, 정확도와 비용 최적화를 요구. 이를 신입 필수 경력으로 적용하지 말 것. [S14][S14]
- **[추정] LLM+규칙 결합:** LLM 단독·규칙 단독·결합 방식의 동일 평가셋 비교. 규칙이 막은 실패, 규칙 때문에 놓친 사례를 함께 제시.
- **[추정] RAG:** 데이터 출처·사용권한·갱신, 검색 실패와 생성 실패 분리, 근거 인용·응답 보류 사례. **XAI:** 설명 화면과 함께 사용자가 오류를 발견하거나 판단을 바꾼 사례. 열람 공고에서 XAI 자체의 가점은 확인되지 않음.
- **[추정] 비용·시간:** 전후 값뿐 아니라 동일 작업량·측정환경·반복 횟수·API 비용 포함 범위 표시. 고객 데이터가 없으면 공개/합성 데이터와 실험임을 명시. 실험상 절감치를 실제 고객 ROI로 쓰지 않기. 평가·비용·기여 요구를 구체화한 제안. [S9][S9]·[S12][S12]·[S14][S14]
- **[추정] 해커톤:** 상장만 분리 진열하지 말고 해당 프로젝트에 대회·주최·연도·상명·내 기여를 묶기. 수상과 운영 성과는 구분. 수상이 배포·검증을 대신한다는 근거는 없음.

## 4. Design implication: 웹 포트폴리오 첫 화면

**아래 전부 [추정] 설계 제안.** 채용사가 요구한 픽셀 규격이 아님. 핵심 경험을 본문에 보여주라는 첨삭과 프로젝트 기여·과정 요구를 적용. [V2][V2]·[V3][V3]·[S12][S12]

1. **상단 56px:** 이름·지원 분야·GitHub·이력서 PDF. 이름보다 프로젝트 결과 제목을 크게. 연락 CTA·역할 표어 삭제.
2. **소개 80–100px:** 소속·졸업 예정·지원 분야 1줄, 실제 해결한 문제를 설명하는 1문장. 거대한 인사말·전면 사진 생략.
3. **대표 프로젝트 1개, 420–480px:** 데스크톱 본문 최대 1,120px, 왼쪽 설명 55%·오른쪽 실제 UI/시연 45%. 제목 → 대상/문제 → 검증 결과 → 내 기여 → 핵심 설계 순서. 제목 32px, 본문 16px, 보조 14px의 세 단계 중심.
4. **펼치지 않아도 보일 것:** 기간, 팀/개인 구분, 내 담당, 개발·실험·배포 상태, 결과와 측정 조건. 성과 미측정이면 ‘미측정’; 템플릿 값은 ‘예시’로 명시. 임의 수치 금지.
5. **시연:** 정지 화면에서 핵심 입출력이 보이고 재생 버튼 즉시 제공. 소리·자동재생·로그인 없이 이해 가능하게. 영상이 없어도 핵심 결과는 읽혀야 함.
6. **기술→기능:** RAG 옆에 ‘문서 근거를 붙여 답변’, 규칙 결합 옆에 ‘금지 조건 차단’, XAI 옆에 ‘판단 근거 확인’. 실제 구현한 기능에만 표시. 축약 구조도 4–6개 노드로 입력→판단→출력 연결.
7. **후속 순서:** 대표 프로젝트 다음 나머지 프로젝트를 최신순. 전체 3개 이상일 때도 첫 화면 하단에 후속 프로젝트 제목·결과가 보이게. 수상 여러 개는 해당 프로젝트 안에 묶고 로고는 보유한 실제 것만 사용.
8. **상세 펼침:** 대안 비교·평가표·실패 사례·코드·발표자료. 버튼도 ‘상세’ 대신 ‘규칙 결합 전후 오류 비교’. 발표자료 웹 미리보기와 PDF 다운로드 병행.
9. **모바일·가독성:** 한 열, 제목 28px, 본문 16px. 문제·결과·내 기여를 시연 위에. 편안한 다크 배경, 포인트 색 하나, 숙련도 막대·장식 타임라인·로고 벽 삭제. `keep-all`, 제목 `balance`, 본문 `pretty`, 숫자 `tabular-nums`.
10. **검수:** 실제 프로젝트 3개로 인사 관점 ‘직무·기여’, 개발 리드 관점 ‘왜·어떻게’, 연구 리드 관점 ‘비교·평가·한계’를 확인. 각 답에 스크롤·펼침·외부 이동이 몇 번 필요한지 기록. 5초 테스트는 사용성 점검이며 채용 통계가 아님.
