## 2. 공통 패턴: 무엇이 면접에서 더 알아볼 이유가 되는가

- **구체적인 문제 해결 경험:** 토스 주니어 공고는 규모와 무관한 해결 경험을 요청하고, 당근은 사용자 문제와 결과를 함께 요구한다. 신입에게 대규모 트래픽 실적이 항상 필수라는 근거는 없다. [S03] [S08]
- **기술을 고른 판단:** 직접 내린 결정과 대안의 장단점이 중요하다. 당근은 만들지 않은 것의 이유도 요청한다. [추정] 기술 배지에는 적용 위치와 해결한 문제를 연결해야 판단력을 읽을 수 있다. [S04] [S08] [S22]
- **팀 성과 속 본인 책임:** 프로젝트 전체 소개와 별도로 직접 설계·구현·검증한 범위를 확인하려 한다. [추정] 근거 없는 기여율 한 숫자보다 담당 기능·결정·PR을 연결하는 편이 검토하기 쉽다. [S04] [S05] [S08]
- **결과와 배움의 연결:** 성공한 기능뿐 아니라 실패 후 개선도 평가 자료가 된다. 연구 인턴 공고도 실패 실험을 분석해 다음 가설로 이어가는 과정을 명시한다. [S02] [S15]
- **기본기와 설명 가능성:** 네이버·쿠팡의 신입 안내와 면접관 기록은 기본기·코드 검증·문제 접근을 함께 다룬다. 프레임워크 목록이 이를 대신하지 못한다. [S09] [S11] [S19] [S22]
- **확인 가능한 품질·협업:** 토스는 코드 구조, 타입, 제품 사용 경험, PR·커밋의 읽기 쉬움을 직접 평가 항목으로 공개했다. [추정] 잔디·커밋 수만으로 이 기준을 충족했다고 판단할 수 없다. [S01]
- **핵심을 본문에서 읽을 수 있는 구성:** 신입 회고와 면접관 댓글 모두 링크를 따라가야 이해되는 구조의 부담을 지적한다. 다만 모든 면접관이 외부 링크를 안 본다거나 노션을 감점한다는 결론은 성립하지 않는다. [S06] [S20]
- **직무에 맞는 선별:** 현업이 직접 서류를 읽는 사례가 있고, 직무 관련 경험을 앞세우라는 안내도 있다. [추정] 지원 역할에 맞는 대표 프로젝트를 먼저 보여주고 전체 이력은 날짜로 추적 가능하게 두는 구성이 적합하다. [S07] [S12] [S14]

| 작동하지 않는 링크·깊은 중첩 | 회고의 피드백 및 커뮤니티 불만으로 확인. 정량 감점이나 자동 탈락 기준은 확인하지 못했다. [S06] [S20] |
| 측정 근거가 없는 성과 숫자 | 공개 자료는 수치와 직접 검증을 권장한다. [추정] 근거가 빠진 숫자는 추가 검증 대상이며, 숫자가 없다는 이유만으로 감점한다고 단정할 수 없다. [S07] [S12] [S21] |
| 복붙 학습 기록·설명 없는 연구 점수 | 복붙은 면접관 의견의 부정 사례. 연구 공고는 분석·검증을 요구한다. [추정] 점수만 있으면 연구 가설과 본인 기여를 판단하기 어렵다. [S15] [S21] |

### 성과 수치는 어떻게 검증 대상으로 바뀌는가

확인한 사실: 기업은 구체적 수치를 권장하지만, 개인의 기술 결정·기여와 문제 해결 과정도 함께 요청한다. 직접 측정·검증 자료를 높이 평가한다는 면접관 의견도 있다. 기업별 내부 수치 검증 문항·허위 판정 기준은 공개 자료에서 확인하지 못했다. [S04] [S08] [S12] [S21]
아래 질문과 제출 형식은 이 근거를 실무 검증으로 확장한 **[추정]**이며, 특정 회사의 실제 면접 질문을 재현한 것이 아니다.

| 의심이 생기는 표현 | 확인 질문 | 포트폴리오에 붙일 최소 근거 |
| --- | --- | --- |
| 개선율·배수만 제시 | 무엇이 얼마나 바뀌었는가? 시간 감소인가, 처리량 증가인가? | 지표 이름·단위·개선 전후 값·계산 기준. 측정하지 않은 수치는 미측정으로 표시. |
| 빠른 응답 시간 하나만 제시 | 데이터량·동시 요청·장비·캐시 조건이 같은가? 평균인가, 상위 지연인가? | 테스트 환경·부하·집계 방식·반복 횟수와 원시 결과 또는 재현 명령. |
| 전체 성과를 개인 성과로 제시 | 본인이 바꾼 부분은 무엇이며 다른 변경의 영향은 없는가? | 팀 결과와 개인 작업을 분리하고 변경 PR·실험 기간·비교 조건을 연결. |
| 큰 사용자·트래픽 수 | 실서비스 관측인가, 합성 부하인가? 어떤 기간의 어떤 집계인가? | 운영/실험 구분, 집계 기간, 지표 정의, 개인정보를 제거한 측정 근거. |
| ML 점수·정확도만 제시 | 기준 모델·데이터 분할·평가셋이 같은가? 누수나 특정 사례 편향은 없는가? | 데이터 출처·분할, baseline, 평가 코드·설정, 실패 사례와 반복 실험 범위. |
| RAG·에이전트 성공 시연만 제시 | 어떤 입력에서 실패하며 무엇을 바꾸면 좋아지는가? | 평가셋·성공 기준·오류 유형·구성 요소 비교, 비용·지연·품질을 함께 기록. |

[추정] 공통 서술 틀은 `문제·제약 → 검토한 선택지 → 내 결정·구현 → 동일 조건의 검증 → 남은 한계`로 둔다. 수치가 없다면 구현 완료 여부, 재현되는 버그의 해소, 테스트나 사용자 피드백처럼 실제로 확보한 증거를 쓰고 수치를 만들지 않는다. 선택 근거·기여·검증을 요구하는 안내를 종합한 제안이다. [S03] [S04] [S08] [S21]

### 해석의 경계

- 이력서의 역할은 지원 직무와 핵심 경험을 빠르게 전달하는 것, 포트폴리오·GitHub는 그 주장의 구체적 증거를 제공하는 것으로 구분할 수 있다. **[추정]** 모든 자료를 동일 분량으로 복제할 필요는 없다. [S01] [S06] [S12]
- 프로젝트 수·GitHub 잔디·스타·수상 개수의 보편적인 합격 기준은 확인하지 못했다. 프로젝트 하나에 집중한 합격 회고도 있으므로 개수를 합격 공식으로 쓰지 않는다. [S06]
- 최근순 구성과 중요도순 구성은 자료마다 다르다. **[추정]** 대표 사례를 먼저 두고 프로젝트 날짜를 일관되게 표시하면 중요도와 시간 흐름을 함께 전달할 수 있다. [S06] [S07]
- S20의 댓글과 연결 원문 S21은 독립 기업 두 곳의 증언으로 세지 않는다. S23은 자동 요약이므로 수치 검증 결론은 공식 안내와 직접 측정에 관한 당사자 글로도 뒷받침했다.
- 열람 실패한 원티드·잡플래닛 인터뷰, 일부 인디스워크·뤼튼 원문 등은 출처 수와 근거에서 제외했다. 검색 요약만으로 내용을 보충하지 않았다. 채용 일정·현재 모집 여부는 이 문서의 조사 대상이 아니다.

## 4. 포트폴리오 웹사이트 설계에 바로 쓰는 시사점

아래 10개는 위 조사와 저장소의 양식 요구를 적용한 **[추정] 설계 체크리스트**다. 5초·프로젝트 3개는 이 템플릿의 검수 조건이며 기업의 공개 채점 기준이 아니다.

- [ ] 1. 첫 화면을 5초 본 사람이 대표 프로젝트의 문제·내 역할·확인된 결과를 각각 한 문장으로 말할 수 있다. [S04] [S06] [S20]
- [ ] 2. 예시 프로젝트 3개 이상을 넣어도 각 프로젝트의 기간·상태·핵심 결과가 펼치기 없이 보이고, 대표 사례와 시간 흐름을 구별할 수 있다. [S06] [S07]
- [ ] 3. 모든 프로젝트에서 팀 전체 결과와 내가 직접 설계·구현·검증한 범위를 구분하고 관련 PR 또는 코드로 연결한다. [S04] [S08]
- [ ] 4. 모든 성과 수치 옆에서 단위·전후 값·측정 조건·근거를 확인할 수 있으며, 가짜 예시·미측정·실험·실운영을 구분한다. [S07] [S12] [S21]
- [ ] 5. 각 대표 프로젝트에 기술 선택 이유·검토한 대안·포기한 점이 있고, 기술 배지가 해당 기능이나 결정으로 연결된다. [S05] [S08]
- [ ] 6. 트러블슈팅 사례에는 증상·원인 후보·검증·수정·재발 방지가 있고, 그림이나 비교 자료로 변화가 드러난다. [S07] [S21]
- [ ] 7. 시연을 페이지에서 바로 볼 수 있고 핵심 흐름·결과를 설명하며, PDF나 외부 링크를 열지 않아도 프로젝트를 이해할 수 있다. [S01] [S06] [S20]
- [ ] 8. GitHub 링크는 해당 저장소나 PR로 바로 열리고, README에서 구현 목적·실행 방법·검증 방법·본인 기여를 찾을 수 있다. [S01] [S10]
- [ ] 9. ML 프로젝트에는 baseline·평가셋·평가 기준·실패 사례·한계가 있고, 논문/발표자료와 연구 코드의 관계를 웹에서 확인할 수 있다. [S05] [S15] [S16]
- [ ] 10. 인사·개발 리드·AI 연구 리드 관점으로 각각 읽어 직무 관련 경험, 구현 책임, 실험 근거를 찾을 수 있는지 확인하고 링크 오류·접근 권한 문제를 모두 점검한다. [S06] [S12] [S14]
