## 1 레이아웃·구성

- 첫 화면에서 대표 프로젝트와 검증 가능한 핵심 결과를 펼치지 않아도 확인하게 배치한다. [impeccable] [hallmark] [taste] [fd]
- 프로젝트는 프로젝트별로 묶고, 각 프로젝트 안의 결과와 수상은 시간순으로 정리한다. [impeccable] [taste]
- 한 화면에는 하나의 주된 메시지만 두고, 섹션마다 제목과 시각 자료가 같은 주제를 설명하게 한다. [hallmark] [taste] [fd]
- 내용의 중요도에 따라 크기와 위치를 달리하고, 모든 항목을 같은 카드로 반복하지 않는다. [impeccable] [hallmark] [taste] [fd]
- 프로젝트 로고는 제공된 자산만 쓰고, 프로젝트명과 핵심 결과를 같은 시야에 둔다. [hallmark] [taste]
- 화면 폭이 줄어도 콘텐츠 컨테이너를 화면 안에 유지하고 가로 넘침을 없앤다. [hallmark] [taste] [fd]
- 넓은 화면에서는 컨테이너 폭을 제한하고 가운데 정렬해 양쪽 여백만 늘린다. [hallmark] [taste]
- 이미지가 들어가는 그리드 열에는 최소 폭 0을 허용하고 제목이 열 밖으로 밀려나지 않게 한다. [hallmark]
- 장식용 눈썹말, 번호, 구분선, 테두리는 정보 구조를 전달할 때만 쓴다. [hallmark] [fd]
- 한 화면의 글은 핵심을 전달하는 분량으로 제한하고, 대표 화면에는 제목·짧은 설명·주요 시각 자료를 우선한다. [hallmark] [taste]
- 링크와 버튼은 실제 목적지나 동작을 제공하고, 행동을 유도하는 연락 CTA를 만들지 않는다. [hallmark] [fd]
- 모든 인터랙션에 키보드 초점 표시를 즉시 보이게 하고, 본문 콘텐츠는 자바스크립트가 꺼져도 읽히게 한다. [hallmark] [taste] [fd]
- 이미지 대체 텍스트를 지정하고 제목 단계와 문서 언어를 올바르게 표시한다. [taste] [fd]

## 2 색

- 배경은 눈이 편한 다크 계열로 설정하고 본문과 배경의 명도 대비를 읽을 수 있게 유지한다. [impeccable] [taste] [fd]
- 색상은 CSS 변수 등 선언된 토큰으로 관리하고 토큰 정의 밖에 색상 리터럴을 쓰지 않는다. [hallmark] [taste]
- 기본 배경·표면·본문·보조 문구·강조색의 역할을 분리하고 강조색은 핵심 상태나 결과에만 쓴다. [impeccable] [fd]
- 장식용 그라디언트와 의미 없는 다색 강조를 넣지 않는다. [hallmark] [taste] [fd]
- 색만으로 상태나 범주를 구분하지 말고 텍스트나 형태 단서를 함께 둔다. [impeccable] [taste]
- 다크 팔레트에서도 보조 텍스트와 테두리가 배경에 묻히지 않는지 확인한다. [impeccable] [taste]

## 3 타이포(한글)

- 글꼴은 두 계열 이내로 정하고 제목과 본문에서 역할을 일관되게 유지한다. [hallmark] [fd]
- 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty`, 한국어 문장은 `word-break: keep-all`을 적용한다. [impeccable] [taste]
- 본문 글자 크기는 읽기 편한 수준으로 유지하고 제목·본문·보조 글자의 크기 단계를 최소화한다. [hallmark] [taste] [fd]
- 제목은 한 가지 무게와 색을 기본으로 쓰고 낱말 하나만 기울임·굵기·색으로 튀게 만들지 않는다. [hallmark] [fd]
- 라벨은 짧은 한국어 문장형 또는 소문자형으로 쓰고 자간을 넓힌 대문자 표기를 피한다. [hallmark] [fd]
- 본문 한 줄 길이는 대체로 80자보다 짧게 유지하고 숫자에는 고정폭 숫자(`tabular-nums`)를 적용한다. [impeccable] [fd]
- 기술 용어는 독자가 이해할 기능이나 결과와 함께 쉬운 한국어로 설명한다. [fd] [im-not-ai]

## 4 모션

- 자동 재생 모션은 시선을 대표 콘텐츠로 안내하는 한두 장면에만 사용한다. [hallmark] [taste] [fd]
- 모션은 불투명도와 변환 속성 위주로 구현하고 `transition: all`과 레이아웃을 바꾸는 애니메이션을 쓰지 않는다. [hallmark] [taste]
- 스크롤 진입마다 반복 재생하는 페이드·슬라이드와 시차 스크롤을 사용하지 않는다. [taste] [fd]
- 포인터·키보드 조작의 결과가 보이도록 상태 변화를 표시한다. [impeccable] [taste] [fd]
- `prefers-reduced-motion: reduce`에서 장식 모션을 끄고 숨겨진 콘텐츠가 남지 않게 한다. [hallmark] [taste] [fd]
- 5초 넘게 반복되는 움직임에는 멈춤 수단을 제공한다. [taste]

## 5 시각화

- 시각 자료는 프로젝트의 실제 산출물·화면·영상·발표 자료를 보여주고, 각 자료에서 기술 선택이 기능에 준 영향을 연결한다. [impeccable] [hallmark] [taste] [fd]
- 시연 영상은 페이지에서 바로 재생할 수 있게 배치하고 발표 자료는 웹에서 열 수 있게 연결한다. [taste] [fd]
- 시각화는 마일스톤 개수 나열 대신 프로젝트의 문제, 작동 방식 또는 결과를 한눈에 설명하게 한다. [impeccable] [hallmark] [taste] [fd]
- 시간 순서를 나타낼 때만 번호나 타임라인을 쓰고, 임의의 막대·점·잔디 모양으로 수치를 꾸미지 않는다. [hallmark] [taste] [fd]
- 측정하지 않은 성과·사용자 수·수상 수·인용·로고를 만들지 않고 출처가 확인되는 값만 표시한다. [hallmark] [taste] [im-not-ai]
- 가짜 예시 데이터는 실제 성과와 혼동되지 않게 명시하고 실제처럼 보이는 수치나 증거로 제시하지 않는다. [hallmark] [im-not-ai]
- 차트나 다이어그램에는 제목·단위·범례를 붙이고 색 외의 구분 단서를 제공한다. [impeccable] [taste]
- 이미지와 영상은 화면 크기에 맞춰 선명하게 표시하고 같은 자료를 이유 없이 반복하지 않는다. [taste]

## 6 카피(한국어 AI 티)

- 각 문장은 사실·행동·결과 중 하나를 구체적으로 말하고 근거 없는 주장을 덧붙이지 않는다. [im-not-ai] [humanizer]
- 프로젝트 설명은 문제, 본인이 한 일, 작동 방식, 확인된 결과 순으로 간결하게 쓴다. [impeccable] [fd] [im-not-ai]
- 추상적 기술어만 나열하지 말고 기술이 사용자 기능이나 관찰 가능한 결과에 미친 영향을 적는다. [fd] [im-not-ai]
- ‘혁신적’, ‘핵심적’, ‘탁월한’, ‘새로운 가능성’ 같은 과장·홍보 표현은 구체적인 사실로 바꾼다. [im-not-ai] [humanizer]
- ‘중요한 역할’, ‘기여하며’, ‘기반으로’, ‘통해’ 같은 모호한 연결은 실제 관계와 행동으로 풀어 쓴다. [im-not-ai] [humanizer]
- 문장마다 주어와 행동 주체를 드러내고 불필요한 피동형과 명사형 나열을 줄인다. [fd] [im-not-ai] [humanizer]
- 같은 문장 구조나 접속어를 연달아 반복하지 않고 문장 길이와 리듬을 자연스럽게 조정한다. [im-not-ai] [humanizer]
- 제목 뒤 첫 문장에서 제목을 반복하지 말고 사실이 끝난 뒤 의례적인 전망 문구를 덧붙이지 않는다. [im-not-ai] [humanizer]
- 화면에서 이미 보이는 순서·구조를 설명하는 문구와 챗봇식 인사·맺음말을 삭제한다. [im-not-ai] [humanizer]
- 실제 근거가 없는 사실은 추정해 채우지 말고 자료가 확인되지 않는 항목은 생략한다. [hallmark] [im-not-ai] [humanizer]
- RAG·멀티턴·XAI·뉴로심볼릭 같은 용어는 맥락에 맞는 쉬운 설명을 먼저 쓰고 필요한 경우 원어를 괄호에 둔다. [fd] [im-not-ai]

## 7 감사 절차

- UI 변경 전 `impeccable context`를 실행해 프로젝트 맥락을 확인하고 대상 파일을 지정한다. [impeccable]
- 화면 구조를 검토할 때 `impeccable critique <대상>`을 실행해 정보 위계와 사용성을 확인한다. [impeccable]
- 반응형·접근성·성능을 검토할 때 `impeccable audit <대상>`을 실행해 기술 품질을 확인한다. [impeccable]
- 최종 시각 품질을 다듬을 때 `impeccable polish <대상>`을 실행하고 발견한 문제를 수정한다. [impeccable]
- Hallmark 감사를 수행할 때 `/hallmark audit <대상>`을 실행하고, 정적 페이지는 `node <hallmark>/scripts/sloplint.mjs <파일> --render`로 실패 항목을 확인한다. [hallmark]
- 카피 감사를 할 때 `/humanize-scan`으로 AI 문체 징후를 진단하고 `/humanize` 또는 `/humanize-redo`로 필요한 문장만 고친다. [im-not-ai]
- 한국어 문장을 검토할 때 `references/quick-rules.md`의 번역투·기계적 병렬·과장·접속어·피동태 항목을 대조한다. [im-not-ai]
- 문장 교정 후 반복 표현·과장·장식용 굵게·챗봇 잔재를 humanizer 기준으로 다시 읽고 사실은 원문과 대조한다. [humanizer]
- 변경된 페이지를 실제 렌더링 크기와 모바일 폭에서 확인하고 초점 표시·가로 넘침·모션 감소 설정을 점검한다. [impeccable] [hallmark] [taste] [fd]
